# Guarded Agent WebUI 重设计

## 目标与设计依据

把当前仅能证明路由可用的朴素 HTML 页面重构为适合持续使用和课程展示的本地 Agent 工作台。界面借鉴现代 Coding Agent 产品的共同模式：任务列表与当前上下文并列、运行状态持续可见、过程日志可审阅、危险动作突出审批，但不复制任何品牌视觉。

保持 FastAPI、Jinja2、原生 CSS/JavaScript 和 localhost-only 架构。不得引入 npm、CDN、远程字体、前端框架、任意命令输入或 Web 凭据输入，以维持离线单文件分发和既有安全边界。

## 视觉系统

- 默认跟随 `prefers-color-scheme`，提供浅色、深色和跟随系统三态主题切换；用户选择存入 `localStorage`。
- 设计 tokens 覆盖背景层级、文字、边框、强调色、成功、警告、危险、圆角、阴影、间距和动效。
- 字体使用系统 UI 字体栈，代码与事件载荷使用系统等宽字体；不加载网络资源。
- 浅色主题使用低饱和灰白背景与深色文字；深色主题使用近黑蓝灰而非纯黑；强调色使用清晰但克制的蓝紫色。
- 所有正文和操作文案使用中文；技术枚举值可同时保留原始英文状态以便诊断。

## 全局布局与导航

桌面端使用三段式工作台：左侧固定导航栏、中央主内容、右侧上下文面板。左栏展示产品标识、固定工作区、任务/审批/记忆/设置导航和本地运行提示。中央区域承担列表、详情与时间线。右栏承担新建任务、当前状态、危险操作或说明。

在窄屏下改为顶部品牌栏、横向可滚动导航和单列内容；右栏内容移动到主内容之前或之后。所有主要交互在 360px 宽度下仍可完成，不产生页面级水平滚动。

导航通过传入模板的 `active_page` 显示当前位置。顶部工具区包含主题切换按钮和 localhost 状态，不增加账户、通知等不存在的功能。

## 页面设计

### 任务工作台

- 中央顶部显示“任务”标题、简短说明和任务数量。
- 任务列表使用可点击卡片，展示目标摘要、状态徽章、创建/更新时间和短 ID；空状态提供明确下一步。
- 右栏是新建任务面板：目标 textarea、已配置验证器 select、安全说明和主要按钮。
- 若已有活动任务，表单仍由后端拒绝；界面不伪造并发能力。

### 任务详情

- 顶部提供返回任务列表、目标、状态徽章和短 ID。
- 中央为纵向事件时间线：图标节点、中文事件名称、时间和可折叠的结构化 payload。
- 右栏显示当前状态、工作区、安全边界和取消按钮。危险/不可逆操作使用次要危险样式，不与主要操作混淆。
- 轮询更新状态徽章、状态文本和时间线；当数据变化时只替换必要 DOM，并支持用户设置的 reduced motion。

### 审批

- 每个待审批动作使用高辨识度风险卡片，展示摘要、状态和审批 ID。
- “拒绝”为安全的次要操作，“批准并继续”为明确的危险确认操作；两者空间分离，避免误触。
- 无待审批时展示带解释的空状态，而不是空列表。

### 记忆

- 中央显示记忆卡片列表，包含类别、内容、来源/可信度（数据可用时）和删除操作。
- 右栏提供新增记忆表单与“仅保存已确认事实”的说明。

### 设置

- 使用信息卡展示工作区、凭据状态、监听地址和安全策略。
- 明确凭据只能通过 CLI 管理，提供可复制但不含秘密的 CLI 命令示例；页面保持只读。

## 组件与模板边界

- `base.html` 负责页面骨架、导航、主题初始化和公共图标符号。
- 新增 `_macros.html` 提供状态徽章、空状态和图标等无业务逻辑的可复用宏。
- 各页面模板只负责其页面信息结构，不复制全局布局。
- `app.css` 按 tokens、reset、layout、components、pages、responsive、accessibility 分区。
- `app.js` 负责主题选择、可折叠区域、复制提示和现有状态轮询，不持有业务真相。
- `web.py` 只增加展示所需的安全派生字段和 `active_page`，不改变治理、审批、凭据与执行语义。

## 可用性与无障碍

- 使用语义化 `header`、`nav`、`main`、`aside`、`section`、表单 label 和按钮类型。
- 键盘焦点清晰；颜色对比目标达到 WCAG AA；状态不只通过颜色表达。
- 触控目标最小约 40px；表单错误沿用服务器响应，不用 JavaScript 绕过验证。
- 尊重 `prefers-reduced-motion`；主题初始化在首屏脚本中完成，降低闪烁。
- 页面标题随页面变化，导航使用 `aria-current`，动态状态使用适度的 `aria-live`。

## 测试与验收

- 先扩展 Web 测试，验证中文页面标题、语义导航、active state、主题控件、状态徽章、审批操作标签和移动端 viewport。
- JavaScript 契约测试验证三态主题、`localStorage` 和轮询更新选择器。
- 保留所有 CSRF、固定工作区、localhost、只读设置、审批绑定和验证器选择安全回归。
- 运行 `make test`、`make quality`、二进制构建与 demo。
- 启动真实 localhost WebUI，对任务、详情、审批、记忆、设置页面进行桌面与窄屏截图检查；验收内容包括层级清晰、无溢出、主题可切换、键盘焦点可见和关键操作无需猜测。

## 明确不做

- 不引入 React/Vue/Tailwind/npm 构建链或远程资源。
- 不增加聊天、代码编辑器、任意 shell、文件浏览、账户系统或公网部署。
- 不改变一次只允许一个活动任务、Mock 默认 provider、CLI 凭据管理和确定性治理边界。
